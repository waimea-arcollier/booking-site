# Project Requirements

## Identified Problem or Need

Currently the system for booking the studios in m block is a paper sign up sheet. When people make errors or want to change their bookings, it results in a messy page, with crossed out and erased names that make the experience difficult for all.


## End-User Requirements

End users for this problem would be students active in m block that book studios regularly, the pfa teachers, and the pfa admin who manages the bookings. They require a simple and easy to use means of booking, with instructions and clear directions. The teachers and admin need priority booking for music lessons and other important appointments. Bookings need to be easily cancelled or deleted


## Proposed Solution

I intend to create a web app to solve this problem, which will have a user friendly ui, and a clear system that allows for booking studios easily and efficiently. The site will have a form to book rooms and displays of what rooms are currently in use. Teachers will be able to remove student bookings and view what students made each booking.


# Relevant Implications

## USEABILITY

The website needs to be simple and easy to use (no training required) and give a good user experience.

### Relevance to the System

A website that is going to be used by students of all year levels and staff will need to follow useability heuristics that make the website easily understood by all ages.

### Impact / Considerations

Useability heuristics i need to consider include: 
User control and freedom - The user needs to easily navigate through the site. My site will have back/home buttons on every page, and a navigational sidebar will be visible at all times.
Error prevention - Users will be unable to book rooms in slots already taken as the option will be disabled. Deletion of bookings, accounts, and log outs will have confirmation pop ups.
Aesthetic and minimalist design - I will display only the necessary information in my menus, and reduce clutter where possible. Where more information is needed a user can click to display more.
Help and documentation - I will have help pages for both logged out and logged in users with tips and FAQs relative to the user. Clear labels and tooltips will also help the user.
